# Live Issues (рабочий журнал живых прогонов)

Актуальные известные проблемы живых прогонов и их статус. Обновляется по
итогам каждого батча. Детали фаз — `PLAN_FINAL_TDD.md`, счётчики — ниже
в `STATUS.md`.

## Открытые

### 0. Серийный event-loop сервера — ИСПРАВЛЕН И ПОДТВЕРЖДЁН LIVE
Pcap + журнал показали: сервер отвечал через 21с после SYN (id=55 в 14:25:57), клиент сдавался на 10-й секунде и рвал сессию (RST) — ответ приходил в мёртвый сокет (Broken pipe).

### 0b. ERR_SSL_PROTOCOL_ERROR в браузере — НАЙДЕН КОРЕНЬ (фикс в дереве)
Туннель идеален (egress=VPS), но браузер рвал TLS-handshake: relay читал
ОДИН раз и возвращал первый сегмент, ServerHello+certs (~4-6КБ) приезжали
обрезанными. curl везло (влезало в сегмент). Фикс: exchange_stream —
write + drain до тишины (idle 300мс, cap 1МБ); keep-alive сокеты
переиспользуются. Пул: воркеры 32 + очередь 256 (burst 180 потоков без
shed; shed TCP DATA = stall поверх client-dedup, только для флуда).
Гейты: 224/224, clippy чист. Нужен редеплой VPS + живой речек браузера. Причина: tunnel_loop — один поток, каждый новый мёртвый таргет стоит 5с dial-таймаута; кулдаун спасал от повторов, но не от первого касания. Фикс: RelayPool (32 воркера), главный цикл только читает/сиалит/пишет. Теория «сервер виснет» — закрыта, он просто тормозил. Подтверждение: verify_client.ps1 — DNS OK + HTTP OK (HTML) против VPS, всё в бюджете.


1. **Петля egress на совмещённом стенде (клиент+сервер на одном хосте).**
   Маршруты клиента (`/1` через TUN) захватывают и собственные сокеты
   сервера: запрос уходит в TUN → памп → снова серверу. Для DNS закрыто
   direct-правилами апстримов; для произвольного TCP на одном хосте
   решения нет по построению. Лечится топологией: тестировать против VPS.
   Статус: задокументировано как ограничение стенда, не баг.
2. **Серийные стойла event-loop сервера.** Каждый первый дайл в мёртвую
   цель — 5с, каждый UDP-релей в тишину — 2с, всё серийно. Частично закрыто:
   dead-target cooldown 30с, пропуск multicast, dial-only на пустых DATA,
   fallback апстримов. Структурно лечится конкурентным релеем (воркеры/
   nonblocking dial) — отдельная задача, не начата.
3. **Модель запрос-ответ вместо стриминга TCP.** Пустой SYN DATA дайлит и
   ждёт чтения, которого не будет; полный дуплекс/продвижение окна не
   реализованы. Покрыто тестами поведения, живой curl — следующий пруф.
4. **Флейк `bind_serve` KeyMismatch в общем прогоне.** Изолированно 5/5
   зелёных; падает только под параллельной нагрузкой workspace. Причина
   в окружении (порты/серты тестов), не в коде tun/пампа.
5. **DPI провайдера подменяет DNS-ответы локально** (чужие A-записи).
   На работу туннеля не влияет (байты идут как есть), мешает только
   интерпретации ручных проверок. Эталон — ответы через VPS-апстрим.
6. **Падения VPS-сервера SIGSEGV (2 случая).** Локальный soak (120 TCP +
   60 UDP, дубли OPEN, тампер) краш не воспроизвёл — shape трафика
   невиновен. Следующий шаг: дебаг на VPS через drop-in
   (`AETHERLINK_DEBUG=1`) + живой батч; либо окружение (контейнер/.NET).
7. **IPv6 обходит v4-туннель.** `curl` без `-4` уходит напрямую по IPv6.
   Известное ограничение; проверки pu только с `-4`.
8. **Ctrl+C через pipe может не доходить до процесса.** Штатный путь —
   команда `down`; плюс auto-down хуки в хосте. `kill -9` покрывается
   журналом `UpState` + `cleanup`.

## Закрытые живыми прогонами

- `wintun open missed` при живом адаптере; friendly-name рассинхрон.
- OEM/cp866-декод `ipconfig`, суффикс `(Основной)`, тип в русских заголовках.
- Новорождённый wintun disabled; `none`-gateway как синтаксическая ошибка.
- Метрика default 30 вместо 5 → захват через `/1` + привязка `if`.
- Сессия wintun умирала в конце выражения; платформа пересоздавалась.
- Пустой `force_cleanup` (только удалял файл) → реальный реплей.
- DNS-тампер рвал весь цикл; тампер flow → скип flow.
- Multicast-шторм вешал цикл на 5с каждый.
- Дубли `up`, stale-DNS в снапшоте, корневые секции конфига вне `client:`.
- Рассинхрон таблиц flow при ошибках send/seal → паника (фикс `09d7fc4`).
- Редеплый поверх живого бинаря (ETXTBSY) → стоп сервиса в скрипте.
- Ручной `netsh set address`/`dnsservers` ходит мимо (состав команд в коде).
- Потерянный `stderr` curl в батчах (`2>&1` обязателен).
- Рассинхрон логов разных эпох → метки времени в дебаге, один батч = один вывод.

## Правила живых прогонов (выученные)

- V2RayN выкл, Telegram/браузер закрыть, иначе шум ×100 флоу.
- Один батч = один вывод; файлы логов читать из репо, не из вставки.
- Сервер и клиент перезапускать из свежих DLL каждый раз.
- `state.json` + таблица маршрутов проверяются до и после.
- Никогда не убивать окно A без последующего `down`/`cleanup`.
